# うねり底スクリーナー

日本株の逆張り投資家向けの銘柄探しアプリです。市場の歪み(会社のせいではなく環境のせいで下がっている株)を、10年チャートのうねりの底で拾うためのものです。

このリポジトリをもとに、**自分専用のアプリ**を作って使います。平日21:17(JST)にGitHub Actionsが自動でデータを更新し、iPhoneのホーム画面から見るだけで使えます。費用はかかりません。

> 表示は銘柄探しの補助で、売買の推奨ではありません。最終判断は決算資料などで必ず確認してください。

## ご利用にあたって(必ずお読みください)

このアプリは、J-Quants の個人向けサービス(私的利用に限る)のデータを使います。J-Quants の[利用目的・ライセンス](https://jpx-jquants.com/ja/help/usage)に沿って、次のように使ってください。

- **J-Quants には、使う人がそれぞれ自分で登録します。** API キーの貸し借りや共有はできません。
- **できあがったアプリを見られるのは、自分と同居の家族だけにします。** URL とパスワードを知人などに教えないでください。少人数・無償でも、第三者への提供にあたります。
- 元のリポジトリの作者は、あなたのデータを預かったり中継したりしません。データの取得から公開まで、すべてあなたの GitHub の中で行われます。

## 用意するもの

- GitHubのアカウント(無料)
- J-Quantsのアカウント(無料プラン)
- 自分で決めるパスワード(アプリを開くときに使います。長めのものにしてください)

パソコンで作業すると楽です。全部で15分ほどと、初回のデータ取得を待つ時間(約1時間)がかかります。

## 自分専用のアプリを作る

### 1. J-Quantsに無料登録してAPIキーを取る

1. [J-Quants](https://jpx-jquants.com/) でユーザー登録し、Freeプランを選びます。
2. ダッシュボードの「APIキー」の画面でキーを発行してコピーします。あとで使います。

### 2. このリポジトリをコピーする

1. GitHubにログインした状態で、このリポジトリのページの緑の **「Use this template」** →「Create a new repository」を押します。
2. 名前(例: `uneri`)を入れ、**Public** を選んで「Create repository」を押します。

コピーには設定ファイル(`.github` フォルダ)も含まれるので、ファイルを手でアップロードする必要はありません。

「Use this template」が見当たらない場合は、元のリポジトリの持ち主に、テンプレートにしてもらうよう伝えてください(下の「リポジトリの持ち主の方へ」)。

### 3. Secretsを登録する

作ったリポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」で、次の2つを登録します。

| 名前 | 中身 |
| --- | --- |
| `JQUANTS_API_KEY` | 手順1のAPIキー |
| `SITE_PASSWORD` | 自分で決めたパスワード |

`SITE_PASSWORD` がないと、平文で公開しないよう実行が止まります。

### 4. Pagesの公開元をGitHub Actionsにする

「Settings」→「Pages」→「Build and deployment」の「Source」を **GitHub Actions** にします。

### 5. 初回の実行

1. 「Actions」タブを開きます。ワークフローを有効にするか聞かれたら有効にします。
2. 左の「毎日の更新」→ 右の「Run workflow」→ 緑の「Run workflow」を押します。
3. 初回は約1時間かかります。緑のチェックになれば完了です。

2回目以降は取得済みのデータを引き継ぐので早く終わります。

### 6. iPhoneのホーム画面に追加する

1. iPhoneのSafariで `https://(GitHubのユーザー名).github.io/(リポジトリ名)/` を開きます。URLは「Settings」→「Pages」にも出ています。
2. パスワードを入れ、「このiPhoneに記憶する」にチェックしたまま「表示する」を押します。
3. 共有ボタン →「ホーム画面に追加」を押します。

以後は平日の夜に自動で更新されます。

## ロット管理を使う(任意・Firebase)

「ロット」タブ(購入計画と保有銘柄の管理)と★(ウォッチ)の端末間の共有には、自分のFirebase(無料)が必要です。使わない場合は飛ばして構いません。そのときは「ロット」タブに「設定が必要です」と出て、★はその端末だけに保存されます。

1. [Firebaseコンソール](https://console.firebase.google.com/)で、**このアプリ専用の新しいプロジェクト**を作ります(Googleアナリティクスはオフで構いません)。ほかのアプリで使っているプロジェクトは使わないでください。料金プランは無料のSparkのままにします。
2. 「Authentication」→「始める」→「Sign-in method」で「メール/パスワード」を有効にします。
3. 「Authentication」→「Users」→「ユーザーを追加」で、自分のメールアドレスとパスワードを登録します。アプリを開くパスワードとは別のものにします。
4. 「Authentication」→「設定」→「ユーザーアクション」で「作成(登録)を許可」をオフにします。他人が登録できなくなります。
5. 「Firestore Database」→「データベースを作成」→ 本番環境モードで作成します。場所は `asia-northeast1`(東京)がおすすめです。
6. Firestoreの「ルール」タブに、このリポジトリの `firestore.rules` の中身を貼り付けて「公開」します。
7. 歯車マーク →「プロジェクトの設定」→「マイアプリ」で「</>」(ウェブ)を押してアプリを登録し、表示された `firebaseConfig` の `{` から `}` までをコピーします。
8. GitHubのリポジトリの「Settings」→「Secrets and variables」→「Actions」→ **「Variables」タブ** →「New repository variable」で、名前を `FIREBASE_CONFIG`、値にコピーした内容を貼り付けて登録します。
9. 「Run workflow」で再実行すると反映されます。

`firebaseConfig` の値は公開されても問題ありません。データはログインと手順6のルールで守られます。Safariとホーム画面のアプリは別扱いなので、それぞれ一度ログインが必要です。

★(ウォッチ)は、ログイン中はFirebaseに保存され、どの端末でも同じものが見られます。ログインしていない間は、その端末だけに保存します。

ほかのロット管理アプリのデータは、そちらからCSVで書き出し、「ロット」タブの「CSVを読み込む」で移せます(列名「コード」「株数」「1株あたり購入金額」「購入済」に対応)。投資金額はCSVに入らないので、もう一度入力してください。

## プッシュ通知を使う(任意)

毎日の更新のあとに、★を付けた銘柄が買い場に近づいたときや、購入予定の銘柄が目標価格に届いたときに、iPhoneへ通知します。当てはまるものがない日は届きません。タップすると、アプリの「お知らせ」(右上のベル)が開き、理由と銘柄の詳細を確認できます。

先に「ロット管理を使う」を済ませてください(通知の届け先と★・購入予定は、ロット管理のアカウントに保存されます)。iPhoneは iOS 16.4 以降で、ホーム画面に追加したアプリが必要です。

1. アプリ右上のベル →「お知らせ」を開き、**「通知用の鍵を作る」** を押して、表示された文字列をコピーします(パソコンで開くと、GitHub に貼り付けやすいです)。この鍵は他の人に見せないでください。
2. GitHubの「Settings」→「Secrets and variables」→「Actions」→「Secrets」タブで、次の3つを登録します。

| 名前 | 中身 |
| --- | --- |
| `VAPID_PRIVATE_KEY` | 手順1でコピーした文字列 |
| `NOTIFY_EMAIL` | ロット管理(Firebase)のログインのメールアドレス |
| `NOTIFY_PASSWORD` | ロット管理(Firebase)のログインのパスワード |

3. 「Run workflow」で更新します。
4. iPhoneのホーム画面のアプリでベル →「この端末で通知をオンにする」を押し、通知を許可します。「テスト通知」で表示を確認できます。

届く条件(同じ状態が続いている間はくり返し通知しません)

- ★の銘柄が、過去の谷の±15%(底値帯)に入った
- ★の銘柄の10年レンジの位置が15%以下になった
- ★の銘柄が、10年位置30%以下で13週線を上回った(反転サイン)
- 購入予定(ロットの購入済でない行)の株価が、入力した購入金額(1株)以下になった

通知の結果は、Actionsの実行結果の「データ更新の結果」に「プッシュ通知: …」として出ます。

## うまく動かないとき

まず「Actions」タブで失敗した実行(赤い×)を開き、赤くなっている手順を確認します。実行結果のページ下部の「データ更新の結果」に、データ源ごとの成否が出ます。

| 症状 | 確認すること |
| --- | --- |
| Actionsに「毎日の更新」が出ない | `.github/workflows/update.yml` があるか。手でアップロードした場合は、隠しフォルダの `.github` が漏れやすいので、「Add file」→「Create new file」でファイル名に `.github/workflows/update.yml` と入れて中身を貼り付けます |
| 「SITE_PASSWORD が設定されていません」 | Secretsの名前のつづり(手順3) |
| 「JQUANTS_API_KEY が設定されていません」、HTTP 401/403 | Secretsの名前と、APIキーが有効か。キーを再発行したら登録し直します |
| 「Get Pages site failed」やデプロイの失敗 | PagesのSourceがGitHub Actionsになっているか(手順4) |
| GitHubの設定ページが404になる | GitHubにログインしているか |
| 「銘柄数が少なすぎるため公開しません」 | Yahooのレート制限の可能性があります。時間をおいて「Run workflow」を押します。前回の公開はそのまま残ります |
| 「ロット」タブに「設定が必要です」と出る | 変数 `FIREBASE_CONFIG` の名前と中身。登録後に「Run workflow」で再実行します |
| 「データを読めません。Firebaseのセキュリティルールを確認してください」 | Firestoreのルールが公開されているか(ロット管理の手順6) |
| 通知が届かない | 「データ更新の結果」の「プッシュ通知」の行を見ます。「未設定」なら Secrets の名前、「ログインできません」なら NOTIFY_EMAIL・NOTIFY_PASSWORD、「端末がない」ならアプリで通知をオンにします |
| 「お知らせ」に「ホーム画面に追加…」と出る | iPhoneでは、ホーム画面に追加したアプリから開いたときだけ通知をオンにできます |
| 信用残の欄に「○週分」と出る | 正常です。掲載が直近5営業日分だけなので、使い始めた日から貯めています |
| 財務が古い | 無料プランは直近12週のデータが取れません。最新の決算はアプリのリンクから株探で確認できます |
| パスワードが通らない | Secretsを変えたら、次の更新のあとで新しいパスワードが有効になります |
| 定期実行が止まった | 60日コミットがないと止まるので、50日ごとに空コミットしています。止まっていたら「Actions」で有効にし直します |

一部のデータ源が失敗しても、ほかのデータで更新は続きます。データは `actions/cache` に保存されており、消えても次回に自動で取り直します(信用残の蓄積だけは取り直せません)。

## 有料プランへの切り替え

J-Quantsのスタンダードプラン(月3,300円)にすると、財務の12週遅れがなくなり、株価・信用残・空売りもJ-Quantsから取るようになります。

1. J-Quantsでプランを変更します。
2. 「Settings」→「Secrets and variables」→「Actions」→「Variables」タブで、`DATA_SOURCE` という名前の変数を値 `jquants` で登録します。
3. 「Run workflow」を押します。初回は10年分の株価を取るため時間がかかります(長いときは複数回に分けて進みます)。

無料に戻すには、変数を消します。

## リポジトリの持ち主の方へ

ほかの人が「Use this template」でコピーできるよう、「Settings」→「General」で **「Template repository」** にチェックを入れてください。コピーされるのはプログラムと手順書だけです。Secrets・変数・取得したデータ・公開中のアプリは、コピー先に渡りません。

## データについて

| データ | 出どころ | 頻度・範囲 |
| --- | --- | --- |
| 株価 | Yahoo!ファイナンス(yfinance) | 10年分の週足を毎回取り直し、直近1か月の日足も取得 |
| 財務・銘柄一覧 | J-Quants API V2 無料プラン | 15か月分。直近12週は取得不可 |
| 機関の空売り | JPX「空売りの残高に関する情報」 | 過去13か月分のExcel |
| 信用残 | JPX「銘柄別信用取引残高」 | 直近5営業日分のPDFを蓄積 |
| 米国の金利・景気 | FRED | CSV |

データはAES-256-GCMで暗号化して公開します(鍵はPBKDF2-SHA256・250,000回)。リポジトリに株価データは入りません。

## 手元で動かす

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -t .
.venv/bin/python -m uneri.main --demo
.venv/bin/python -m http.server -d public-demo 8000
```

`--demo` はAPIキーなしで架空の銘柄を使って最後まで動かします。`http://localhost:8000/` で確認できます。

## ファイルの構成

| 場所 | 内容 |
| --- | --- |
| `.github/workflows/update.yml` | 毎日の自動実行 |
| `uneri/` | データ取得・計算・暗号化(`main.py` が入口) |
| `site/` | 画面(`index.html`=うねり底・人気株・検索・ロット、`sector.html`=セクター、`lots.js`=ロット管理、`alerts.js`・`sw.js`=通知) |
| `tests/` | テスト |
| `firestore.rules` | ロット管理のデータを本人だけに限るルール |
